# Peta Kepatuhan UU PDP & ISO 27001 🗺️

Dokumen ini memetakan bagaimana tantangan teknis di dalam **PDP Koans (Django Edition)** terhubung langsung dengan aspek hukum **Undang-Undang Pelindungan Data Pribadi (UU PDP)** serta kontrol standar keamanan **ISO 27001**.

---

## 📋 Tabel Cakupan Kepatuhan

| Tantangan Koans | Aspek Hukum (UU PDP) | Kontrol Standar (ISO 27001) | Detail Bahasan Teknis yang Diimplementasikan |
| :--- | :--- | :--- | :--- |
| **Koan 01: Data Minimisation**<br>`koans/k01_data_minimization/` | **Pasal 16 UU PDP**:<br>Batasan pemrosesan data | **Control A.8.11**:<br>Data masking & pembatasan akses | **Prinsip Minimisasi Data & Masking**:<br>• **[Basic]**: Menghapus field tidak relevan/berlebihan dari model database.<br>• **[Intermediate]**: Penyamaran data sensitif (context-aware masking) yang hanya terbuka bagi DPO.<br>• **[Advanced]**: Verifikasi penghapusan kolom fisik dari database dengan query SQL langsung. |
| **Koan 02: Explicit Consent**<br>`koans/k02_explicit_consent/` | **Pasal 20 & 21 UU PDP**:<br>Persetujuan tertulis/terekam | **Control A.5.15**:<br>Manajemen hak akses & persetujuan | **Dasar Pemrosesan & Bukti Persetujuan**:<br>• **[Basic]**: Menolak registrasi jika persetujuan layanan utama tidak diberikan.<br>• **[Intermediate]**: Mencatat log persetujuan audit (Consent Log) lengkap dengan metadata (IP, waktu).<br>• **[Advanced]**: Penerapan *Consent Unbundling*—tidak memblokir registrasi jika opsional marketing ditolak. |
| **Koan 03: Data Security**<br>`koans/k03_data_security/` | **Pasal 39 UU PDP**:<br>Kewajiban menjaga keamanan data | **Control A.8.24**:<br>Penggunaan kriptografi (Enkripsi *at-rest*) | **Keamanan Data & Kriptografi**:<br>• **[Basic]**: Enkripsi dua arah kolom database menggunakan kunci utama (AES/Fernet).<br>• **[Intermediate]**: Dekripsi otomatis saat data diambil dari database melalui custom model field.<br>• **[Advanced]**: Manajemen masa tenggang rotasi kunci dengan enkripsi cadangan/fallback keys jika dekripsi utama gagal. |
| **Koan 04: RBAC & Access Audit Trail**<br>`koans/k04_rbac_audit/` | **Pasal 40 UU PDP**:<br>Aturan pembatasan akses data | **Control A.8.2 / A.5.15**:<br>Hak akses & perekaman log audit | **Role-Based Access Control & Log Audit**:<br>• **[Basic]**: Membatasi akses view data sensitif hanya untuk peran Data Protection Officer (DPO).<br>• **[Intermediate]**: Pencatatan otomatis aktivitas akses DPO ke dalam log audit (`AccessAuditLog`).<br>• **[Advanced]**: Rantai log antipenyamaran (*Tamper-Resistant Log Chain*) menggunakan tanda tangan HMAC-SHA256 yang saling terikat dengan `SECRET_KEY`. |
| **Koan 05: Data Portability**<br>`koans/k05_data_portability/` | **Pasal 7 & 13 UU PDP**:<br>Hak pemindahan data (portabilitas) | **Control A.5.15**:<br>Manajemen permintaan subjek data | **Portabilitas Data & Proteksi IDOR**:<br>• **[Basic]**: Verifikasi konteks pengguna untuk mencegah serangan IDOR/BOLA pada ekspor data.<br>• **[Intermediate]**: Agregasi data lintas tabel (profil, persetujuan, transaksi) ke dalam JSON terstruktur.<br>• **[Advanced]**: Simulasi ekspor data asinkron dengan pelacakan status job (polling) untuk volume besar. |
| **Koan 06: Data Breach Response**<br>`koans/k06_breach_response/` | **Pasal 35 UU PDP**:<br>Notifikasi kegagalan data pribadi | **Control A.5.24**:<br>Manajemen insiden keamanan informasi | **Isolasi Akun & Laporan BPPA**:<br>• **[Basic]**: Pemblokiran akses akun (karantina) jika pengguna terkompromi (`is_compromised`).<br>• **[Intermediate]**: Penyusunan otomatis draf laporan notifikasi kegagalan data resmi berstandar Pasal 35.<br>• **[Advanced]**: Kontainmen insiden otomatis—mendeteksi aktivitas mencurigakan dan mengisolasi akun secara dinamis. |
| **Koan 07: Data Deletion & Anonymisation**<br>`koans/k07_deletion_anonymisation/` | **Pasal 16 & 43 UU PDP**:<br>Hak penghapusan data / Hak untuk dilupakan | **Control A.8.10 / A.8.14**:<br>Penghapusan informasi & manajemen redundansi | **Penghapusan vs Anonimisasi**:<br>• **[Basic]**: Penghapusan permanen (*hard delete*) pada data pengenal langsung (identitas/profil).<br>• **[Intermediate]**: Anonimisasi/pseudonimisasi riwayat transaksi finansial dengan transaksi database atomik.<br>• **[Advanced]**: Alur penghapusan tertunda secara asinkron dengan antrean database (`DeletionRequest`). |
| **Koan 08: Consent Withdrawal**<br>`koans/k08_consent_withdrawal/` | **Pasal 15 & 40 UU PDP**:<br>Hak untuk menarik persetujuan | **Control A.5.15**:<br>Manajemen hak akses & persetujuan | **Alur Revokasi Persetujuan**:<br>• **[Basic]**: Pencatatan penarikan persetujuan (`consent_given = False`) dan deaktivasi akun instan.<br>• **[Intermediate]**: Menjamin konsistensi proses deaktivasi & logging via transaksi database atomik.<br>• **[Advanced]**: Pencabutan instan token JWT yang aktif dengan mekanisme daftar hitam (*Token Blacklist*). |
| **Koan 09: Purpose Limitation**<br>`koans/k09_purpose_limitation/` | **Pasal 16 & 27 UU PDP**:<br>Pembatasan tujuan pemrosesan data | **Control A.5.15**:<br>Manajemen hak akses & verifikasi persetujuan | **Pemisahan Tujuan Data**:<br>• **[Basic]**: Membatasi pengiriman promosi hanya kepada pengguna yang memiliki persetujuan pemasaran.<br>• **[Intermediate]**: Pemisahan kampanye berbasis kategori persetujuan pemasaran granular.<br>• **[Advanced]**: Penyaringan komprehensif (mengecualikan pengguna terblokir/tidak aktif/terkompromi). |
| **Koan 10: Data Retention Policy**<br>`koans/k10_data_retention/` | **Pasal 16 & 43 UU PDP**:<br>Pemusnahan data pribadi / Retensi | **Control A.8.10**:<br>Penghapusan informasi | **Pembersihan Data Otomatis**:<br>• **[Basic]**: Penghapusan log yang kedaluwarsa berdasarkan ambang batas waktu (masa retensi).<br>• **[Intermediate]**: Penghapusan batch secara bertahap (chunked delete) untuk mencegah lock database.<br>• **[Advanced]**: Pengarsipan otomatis log kedaluwarsa ke dalam berkas JSON sebelum dihapus secara fisik. |
