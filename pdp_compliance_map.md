# PDP & ISO 27001 Compliance Map 🗺️

This document maps how the technical challenges in **PDP Koans (Django Edition)** directly align with the legal compliance requirements of **Indonesian Personal Data Protection Law (UU PDP)** and **ISO 27001 security controls**.

---

## 📋 Compliance Coverage Table

| Koan Challenge | Legal Aspect (UU PDP) | Standard Control (ISO 27001) | Technical Implementation Topic |
| :--- | :--- | :--- | :--- |
| **Koan 01: Data Minimisation**<br>`koans/k01_data_minimization/` | **Article 16 UU PDP**:<br>Limits of data processing | **Control A.8.11**:<br>Data masking & access restriction | **Data Minimisation & Masking**:<br>• **[Basic]**: Removing unnecessary/excessive fields from the database model.<br>• **[Intermediate]**: Context-aware masking restricting cleartext data exposure only to DPOs.<br>• **[Advanced]**: Physical column deletion verification using raw database schema introspection. |
| **Koan 02: Explicit Consent**<br>`koans/k02_explicit_consent/` | **Articles 20 & 21 UU PDP**:<br>Written/recorded consent requirement | **Control A.5.15**:<br>Access control & consent management | **Processing Foundations & Proof of Consent**:<br>• **[Basic]**: Rejecting registration requests when core service consent is not provided.<br>• **[Intermediate]**: Recording structured consent audit logs (Consent Logs) with metadata (IP, time).<br>• **[Advanced]**: Consent Unbundling—ensuring optional marketing rejection does not block registration. |
| **Koan 03: Data Security**<br>`koans/k03_data_security/` | **Article 39 UU PDP**:<br>Duty of data security preservation | **Control A.8.24**:<br>Use of cryptography (Encryption *at-rest*) | **Data Security & Cryptography**:<br>• **[Basic]**: AES/Fernet encryption of specific database columns using a primary key.<br>• **[Intermediate]**: Automatic decryption on retrieval through a custom Django model field.<br>• **[Advanced]**: Key rotation grace period supporting decryption fallback with deprecated keys. |
| **Koan 04: RBAC & Access Audit Trail**<br>`koans/k04_rbac_audit/` | **Article 40 UU PDP**:<br>Restricted access control rules | **Control A.8.2 / A.5.15**:<br>Access rights & audit logging | **Role-Based Access Control & Audit Trails**:<br>• **[Basic]**: Restricting access to sensitive data endpoints using a DPO role permission check.<br>• **[Intermediate]**: Automatic logging of DPO access activities into an audit trail (`AccessAuditLog`).<br>• **[Advanced]**: Tamper-resistant log chaining using HMAC-SHA256 signature chains with `SECRET_KEY`. |
| **Koan 05: Data Portability**<br>`koans/k05_data_portability/` | **Articles 7 & 13 UU PDP**:<br>Data subject rights to portability | **Control A.5.15**:<br>Data subject requests & access control | **Data Portability & IDOR Protection**:<br>• **[Basic]**: User context validation to prevent IDOR/BOLA attacks on data exports.<br>• **[Intermediate]**: Aggregating data across profile, consent logs, and transactions into structured JSON.<br>• **[Advanced]**: Simulated asynchronous export with status tracking (polling) for large-scale data. |
| **Koan 06: Data Breach Response**<br>`koans/k06_breach_response/` | **Article 35 UU PDP**:<br>Data breach notifications | **Control A.5.24**:<br>Information security incident management | **Breach Containment & BPPA Reporting**:<br>• **[Basic]**: Locking out and quarantining compromised accounts (`is_compromised`).<br>• **[Intermediate]**: Generating official UU PDP Article 35-compliant breach notification reports.<br>• **[Advanced]**: Automatic containment logic triggering lockouts dynamically based on anomalous access patterns. |
| **Koan 07: Data Deletion & Anonymisation**<br>`koans/k07_deletion_anonymisation/` | **Articles 16 & 43 UU PDP**:<br>Right to erasure / Right to be forgotten | **Control A.8.10 / A.8.14**:<br>Information deletion & redundancy management | **Erasure vs Anonymisation**:<br>• **[Basic]**: Permanently hard-deleting direct identifiers (identity, profile logs).<br>• **[Intermediate]**: Anonymizing transaction histories while maintaining atomic transaction consistency.<br>• **[Advanced]**: Asynchronous delayed deletion queue handling (`DeletionRequest`) with immediate account lockout. |
| **Koan 08: Consent Withdrawal**<br>`koans/k08_consent_withdrawal/` | **Articles 15 & 40 UU PDP**:<br>Right to withdraw consent | **Control A.5.15**:<br>Access control & consent management | **Consent Revocation Flow**:<br>• **[Basic]**: Logging revocation events (`consent_given = False`) and immediately deactivating accounts.<br>• **[Intermediate]**: Ensuring transaction atomicity for consistent deactivation and logging state.<br>• **[Advanced]**: Revoking active user JWT token sessions instantly via a token blacklist database. |
| **Koan 09: Purpose Limitation**<br>`koans/k09_purpose_limitation/` | **Articles 16 & 27 UU PDP**:<br>Limitation of data processing purpose | **Control A.5.15**:<br>Access control & consent verification | **Data Purpose Separation**:<br>• **[Basic]**: Restricting promotion broadcasts only to users who have given explicit marketing consent.<br>• **[Intermediate]**: Granular category-based marketing consent segment filtering.<br>• **[Advanced]**: Applying a full compliance sieve excluding blocked, inactive, and compromised accounts. |
| **Koan 10: Data Retention Policy**<br>`koans/k10_data_retention/` | **Articles 16 & 43 UU PDP**:<br>Deletion of personal data / Retentions | **Control A.8.10**:<br>Information deletion | **Automated Data Purging**:<br>• **[Basic]**: Purging expired logs based on retention thresholds (time delta).<br>• **[Intermediate]**: Chunked database deletions in loops to prevent large-scale transaction locks.<br>• **[Advanced]**: Automatically archiving expired records to a JSON file before physical deletion. |
